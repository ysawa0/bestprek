# Writing Tools

Draft or revise prose against a mandatory rule pack. The pack sets review breadth, not whether its rules are optional.

## 1. Choose the pack

Use an explicit user choice first: `pack 1` / `core`, `pack 2` / `polish`, or `pack 3` / `full`. Otherwise route from the actual deliverable:

| Pack | Mandatory rules | Automatic trigger | Read only |
| --- | --- | --- | --- |
| 1 — Core | 12 | Default: everyday messages, short answers, working drafts, quick revisions. | [Core](packs/01-core.md) |
| 2 — Polish | 25, including Core | A multi-section document or important professional/external prose: design doc, proposal, resume, application, or substantive stakeholder email. | [Polish](packs/02-polish.md) |
| 3 — Full | All 55 | An explicit exhaustive/all-55 request, or a final high-consequence deliverable: board/executive submission, funding submission, official public statement, publication-ready manuscript. | [Full](packs/03-full.md) |

Apply the highest matching automatic trigger. A recipient's title alone does not make a rough draft Full. Respect an explicit pack even when automatic routing would choose another. Escalate an automatically selected pack only when the task's scope or final-use stakes change; never escalate just because more rules exist. When scope is unclear, use Core and proceed.

Done: One pack is selected and read. Packs are cumulative: read the selected file once, not its lower packs as well. The complete selected requirements are already in that file; reading the canonical references again is unnecessary.

## 2. Lock the brief and evidence

Identify the reader, purpose, form, voice, length, and editing scope. Preserve facts, quantities, units, dates, names, attribution, quotations, uncertainty, causality, and ownership. Keep measurements distinct from projections. Verify added factual claims or mark the gap; invent scene details only in fiction. Keep exact quotations and text outside the authorized editing scope unchanged.

Classify the form as report, story, or hybrid. Review breadth never changes genre: Full does not turn a factual memo into a story. A selected rule governs every occurrence of its stated target. A genuinely absent target has no violation; do not add dialogue, characters, metaphors, or suspense just to activate a rule. Preserve the specific genre duties stated in the selected rules.

Done: The evidence and editable scope are identified; missing information remains explicit.

## 3. Draft, revise, check

Execute selected preparation rules before drafting and selected review rules afterward. Revise structure, then paragraphs, then sentences and words. Apply every selected requirement, including Rule 2's 2–3–1 order. Preserve factual qualifiers by repositioning them, not deleting them.

Check each selected rule's pass condition. Fix failures and recheck affected requirements. Accept `NO TARGET` only for the stated target's absence and `USER OVERRIDE` only for an explicit conflicting instruction. Preserve the narrow scope of requests such as spelling-only edits. Unselected rules require neither loading nor individual audit entries.

Done: The active pack passes, evidence is intact, and the requested format and length are met. Stop polishing at that point. Disclose an irreconcilable conflict rather than claiming a pass.

## 4. Deliver

Return the requested prose, with only essential gap/conflict notes. Keep the pack choice and checks out of ordinary output. For an explicitly requested audit, identify the pack and report its rule numbers with pass/fail, absent-target, or override results. Full audits account for all 55; smaller-pack audits account for their selected rules only.

## Maintenance

For rule changes, read the matching numbered file in `references/`. For pack membership, generation, validation, and source boundaries, read [README](README.md). For behavioral evaluation, use [regression cases](evals/cases.md). Maintenance files are not runtime prerequisites.
